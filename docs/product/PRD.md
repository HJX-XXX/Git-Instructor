# Git 可视化教学沙箱 · 产品文档

- 版本：MVP v0.1（待评审）
- 日期：2026-02-14
- 形态：纯前端 Web 单页应用
- 面向：日常会用 Git、但想系统练命令行的 Java / 后端开发者

---

## 1. 一句话

在浏览器里输入 Git 命令，立刻看到提交图上的分支与指针怎么变，并有中文提示框解释「刚刚发生了什么」、速查常用语句。

## 2. 背景与问题

| 现状 | 痛点 |
|------|------|
| 日常用 GUI / IDE 的 Git 面板 | 看不见命令对 DAG 的真实影响 |
| 需要时再搜博客 | 缺「随叫随到」的语句速查 |
| 在真实仓库里试命令 | 怕把分支搞乱，不敢 reset / rebase |

因此需要一个**可无限重置**的模拟环境：只改内存模型，不碰真实仓库。

## 3. 产品目标（MVP）

1. **命令 → 图**：执行核心 Git 命令后，提交图更新，并高亮新建的 commit、移动的分支/HEAD。
2. **提示方框**：左侧分类速查；右侧每次执行后的中文讲解。
3. **开箱即玩**：预置 `main` 上 3 个提交的演示仓库，点「重置沙箱」一键恢复。
4. **安全**：全程模拟，永不执行真实 `git`。

**非目标（MVP 不做）**

- 远程（fetch / pull / push）、stash、cherry-pick、交互式 rebase
- 真实文件工作区 / 暂存区
- 关卡式课程、账号、进度系统
- Electron / 移动端适配（窄屏仅保证可滚动堆叠）

## 4. 用户与场景

**主用户**：后端开发，会提交代码，但对分支模型命令不熟。

**典型场景 A — 看懂 merge**

1. 在 `main` 上 commit 几次  
2. `git switch -c feature` 再 commit  
3. `git switch main` 后 `git merge feature`  
4. 观察：何时出现合并提交（双父节点），何时只是 fast-forward  

**典型场景 B — 敢用 reset**

1. 在错误分支上多 commit 了两次  
2. `git reset --soft HEAD~2` / `--hard HEAD~2`  
3. 对比：分支 tip 怎么回退，讲解框说明 soft / mixed / hard 的差别  

**典型场景 C — 速查**

1. 左侧搜「删分支」  
2. 点击卡片填入终端  
3. 改参数后回车执行  

## 5. 功能范围

### 5.1 命令集（模拟）

| 命令 | 说明 |
|------|------|
| `help` | 列出支持命令 |
| `git status` | 当前分支、是否干净、HEAD 指向 |
| `git commit -m "<msg>"` | 在当前 tip 上新建提交 |
| `git branch <name>` | 在当前 tip 建分支 |
| `git branch -d` / `-D <name>` | 删分支；`-d` 拒绝未合并 tip |
| `git switch <name>` / `git checkout <name>` | 切换分支 |
| `git switch -c` / `git checkout -b <name>` | 新建并切换 |
| `git merge <name>` | FF 或双父 merge commit |
| `git reset --soft\|--mixed\|--hard HEAD~n` | 移动当前分支 tip |
| `git revert <hash>\|HEAD` | 生成反向提交 |
| `git rebase <branch>` | 把当前分支独有提交重放到目标 tip |
| `git log` / `--oneline` | 终端文本日志 |

输入可省略前缀 `git `。错误命令返回中文说明，**不修改图状态**。

### 5.2 提交图

- 时间轴：新提交在上  
- 节点：圆形 commit，颜色区分；merge 显示双父连线  
- 标签：分支名贴在 tip 旁；HEAD 用橙色强调  
- 动画：新节点进入、引用标签移动并短脉冲  

### 5.3 提示与讲解

**左栏 · 速查方框**

- 分类：初始化与提交 / 分支 / 切换 / 合并与变基 / 回退 / 查询  
- 卡片：语法、一句话用途、「填入终端」按钮  
- 支持关键词过滤  

**右栏 · 刚刚发生了什么**

- 标题（例：「创建合并提交」）  
- 摘要 1–2 句  
- 细节：与真实 Git 对照时的注意点  
- 相关命令：可点击跳到速查  

### 5.4 顶栏

- 产品名  
- 「重置沙箱」  
- 简短使用说明入口（气泡/折叠即可）  

## 6. 交互流程

```text
输入命令 → 解析
    ├─ 非法 → 终端红字提示，图不变
    └─ 合法 → applyCommand
              ├─ 成功 → 替换仓库状态 → 图动画 → 讲解框更新 → 终端 stdout
              └─ 业务拒绝（如删当前分支）→ 中文拒绝原因，图不变
```

键盘：终端内 `Enter` 执行；`↑` / `↓` 浏览历史。

## 7. 界面结构（桌面优先）

```text
┌──────────────────────────────────────────────────────────┐
│  Git 可视化教学沙箱                    [重置沙箱] [说明]   │
├────────────┬─────────────────────────────┬───────────────┤
│  速查提示  │        提交图（SVG）         │  刚刚发生了什么 │
│  搜索框    │                             │               │
│  分类卡片  │                             │  标题/摘要/细节 │
│            ├─────────────────────────────┤  相关命令      │
│            │  终端（深色条）              │               │
│            │  历史输出 + 输入行           │               │
└────────────┴─────────────────────────────┴───────────────┘
```

- 最低目标宽度约 1100px；更窄时：图上、终端中、速查/讲解改为下方页签或堆叠。  
- 配色：浅色工作台底 `#F5F6F8`，白卡片，终端深蓝黑；HEAD/强调橙 `#F97316`；commit 绿 `#22C55E`。  
- 字体：UI 系统无衬线 + 中文黑体；命令与 hash 等宽。

## 8. 技术方案（摘要）

| 项 | 选型 |
|----|------|
| 框架 | React + TypeScript + Vite |
| Git | 自研内存模拟引擎（纯函数） |
| 状态 | React `useState` / `useReducer`（MVP 不引入 Redux） |
| 图 | 自研布局 + SVG |
| 测试 | Vitest：解析器 + `applyCommand` 核心路径 + 布局 |
| 部署 | `npm run build` 静态资源，任意静态托管 |

**仓库状态模型（简化）**

- `commits`: id → { parents, message }  
- `branches`: 名 → tip id  
- `head`: 分支 或 游离 commit  
- 装饰字段：工作区文件名列表、dirty 标记（服务 status 文案）  

## 9. 验收标准（MVP）

1. 打开页面即可看到演示提交图与当前 `main`。  
2. 能完成「建分支 → 提交 → 切回 → merge」，图与讲解正确。  
3. `reset --hard/soft`、`revert`、`rebase` 行为与讲解符合上文语义。  
4. 非法命令不改状态；重置后与初始状态一致。  
5. 速查可过滤、可填入终端。  
6. `npm run lint` / `npm test` / `npm run build` 通过。

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 模拟语义与真 Git 不一致 | 讲解框标明「教学简化点」；文档列出未实现命令 |
| 图布局交叉难看 | 固定 demo 规模；lane 分配做确定性测试 |
| 命令解析边界多 | 先支持文档化子集，错误信息可教用户正确语法 |
